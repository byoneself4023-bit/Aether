# 면접 대비

## 30초 스토리

> "S&P 500 종목을 선택하면 Markowitz 최적화로 비중을 계산합니다. 입력 민감도 문제를 Shrinkage로 보완해서 비중 변동성 40% 감소를 확인했습니다. Walk-forward로 미래 정보 사용을 방지하고, 거래비용 0.1%를 반영했습니다. LLM 챗봇이 RAG로 '왜 이 비중인지' 설명합니다."

------

## 채용공고 매핑

| 채용공고 요구사항         | Aether에서 증명       |
| ------------------------- | --------------------- |
| "LLM 기반 서비스 개발"    | Gemini + ChromaDB RAG 챗봇  |
| "RAG 파이프라인 구축"     | Chroma 벡터 검색      |
| "마이크로서비스 아키텍처" | Spring Boot + FastAPI |
| "모델 모니터링 경험"      | MLflow 실험 추적    |

------

## 예상 질문 — 핵심

| 질문                 | 답변                                                         |
| -------------------- | ------------------------------------------------------------ |
| "왜 Markowitz?"      | 입력 민감도 문제 확인 → Shrinkage 적용 → 비중 변동성 40% 감소 실험 결과 |
| "백테스팅 어떻게?"   | Walk-forward로 시간순 분리, 거래비용 0.1% 반영               |
| "yfinance 괜찮아?"   | 프로젝트용, 실서비스는 유료 데이터 필요 인식                 |
| "Survivorship bias?" | 인정 + 문서화, 실서비스는 시점별 데이터 필요                 |

------

| "혼자 다 했어요?"     | 전체 파이프라인 이해 + API 스펙 먼저 정의 + 서비스 간 계약 명확화 |

## 예상 질문 — 금융 수학

| 질문                       | 답변                                                  |
| -------------------------- | ----------------------------------------------------- |
| "수익률 정규분포?"         | Fat tail 인식, VaR + 몬테카를로로 보완                |
| "VaR 95% 나머지?"          | CVaR이 더 나은 지표, 향후 추가                        |
| "샤프 비율 높으면 좋아요?" | 변동성 작으면 높아 보이는 함정, 절대 수익도 함께 확인 |
